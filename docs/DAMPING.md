# RHEM 阻尼抑制 v0.6.0

## 结论

`v0.6.0` 新增可选的 `DampingSuppressor`，默认关闭。它不判断业务对错，只给运行期自动进化增加稳定性边界：

- 死区：证据计数未达到设定下限时，不触发自动并库动作；
- A-B-A 振荡检测：从补丁历史中发现“改 A、改 B、又改回 A”的反复摆动；
- 反悔率检测：同一目标反复经历“生效、回滚、再生效”时触发告警；
- 冷却：发现振荡或反悔后，冻结该目标的自动进化动作一段时间；
- 解冻：冷却到期后通过新补丁清除冻结状态，原动作才可继续；
- 规则降权：规则反悔时可生成 `distill_rule` 补丁，将规则降权并禁用。

它不是“稳定器已经证明优于无阻尼”。它只是把一组可审计、可回滚、默认关闭的稳定性治理动作提供出来，供试点和后续验证。

## 为什么需要阻尼

门控、蒸馏、反哺和反馈环主要回答“收什么、什么时候收、什么样的记录更值得留”。它们没有单独回答：

> 当自动改动本身反复摆动时，系统应该停下来多久、停哪些动作、如何留下证据？

阻尼抑制补的是这个稳定性问题。它与门控配合，但不替代门控：

- 门控管进入自动动作前的证据门槛；
- 阻尼管进入动作后的振荡、反悔和冷却；
- 两者都不改变护栏域和人工审批边界。

## 机制

### 1. 死区

`DampingSuppressor.dead_zone_occurrences` 定义阻尼层的最小发生次数。未达到时返回：

```json
{
  "allowed": false,
  "action": "dead_zone",
  "reason": "damping_dead_zone"
}
```

死区不等于替换门控。实际运行中，门控仍先执行；如果门控门槛高于阻尼死区，门控仍是更严格的上限。

### 2. A-B-A 振荡

阻尼从补丁动作中提取稳定指纹，例如：

```text
alias:shanghai
rule:rule:damping:regret
term:ZL-9
process:deadlock_detection_s,max_retries
```

在滑动窗口中观察指纹序列。出现 `A -> B -> A` 时，说明同一目标可能被反复修改，触发：

```json
{
  "allowed": false,
  "action": "freeze_oscillation",
  "reason": "oscillation_detected"
}
```

该判断只使用补丁顺序、动作指纹和状态，不调用 LLM，不推断业务语义。

### 3. 反悔率

对同一目标的补丁状态统计：

- `active`：曾经生效；
- `rolled_back`：被回滚；
- `rolled_back -> active`：一次反悔。

反悔率计算方法为：

```text
反悔事件数 / 生效次数
```

当反悔事件数和反悔率同时超过阈值时，返回 `freeze_regret`。该指标是账本启发式，不是统计置信度。

### 4. 冷却与解冻

触发冻结时会创建 `set_damping_control` 补丁，记录：

- 指纹和错误类别；
- 触发原因；
- 阻尼系数；
- 冷却截止时间；
- 是否需要人工复核；
- 证据摘要和补丁 ID。

冷却期间，自动动作返回 `damping_cooldown`；人工审批不被冻结。冷却到期后，下一次评估会创建 `clear_damping_control` 补丁解冻，再继续原有流程。

### 5. 阻尼系数

当前参考实现使用振荡和反悔事件数计算 `coefficient`，并据此延长冷却时长：

```text
cooldown = base_cooldown_hours * (1 + coefficient)
```

系数只作用于冷却治理，不直接修改业务答案、规则方向或护栏域。

## 使用方式

```python
from rhem import DampingSuppressor, LearningEngine, RhemStore

store = RhemStore("./rhem_store")
engine = LearningEngine(
    store,
    damping=DampingSuppressor(),
)
```

默认不传 `damping` 时，行为与此前版本一致：

```python
engine = LearningEngine(store)
```

可在单个现场先只启用冷却治理，观察 `damping_decision`、补丁和回滚记录，再决定是否调整阈值。

## 补丁与审计

阻尼相关状态位于 `damping_state`，其修改必须经过统一补丁：

- `set_damping_control`：设置冻结控制；
- `clear_damping_control`：清除已到期或人工解除的冻结；
- `distill_rule`：在反悔场景下将规则降权并禁用；
- `damping_plan`：将本轮判断写入补丁和补丁元数据。

回滚补丁会恢复阻尼控制状态；回滚顺序约束仍由 `RhemStore` 执行。

## 护栏边界

- 阻尼只影响自动进化动作的时机和速度；
- 阻尼不改变错误类别、对错标准、业务规则内容或护栏域；
- 强制冷却不冻结人工审批；
- 任何自动冷却、解冻和降权都必须留下补丁并支持回滚；
- 当前实现不把 `coefficient` 解释成真实风险概率。

## 已验证与未验证

当前测试验证：

- 默认 `LearningEngine(store)` 不受影响；
- 死区会在计数不足时拦截自动并库；
- A-B-A 补丁序列可以触发冻结，并可回滚控制状态；
- 冷却期间自动动作被拦截，到期后可解冻并继续；
- 反悔规则可以降权，回滚后恢复启用状态。

当前不声称：

- 阻尼阈值已经在真实长尾上达到统计最优；
- 阻尼一定能减少生产误判反弹或维护成本；
- 补丁序列足以代表所有真实振荡模式；
- 单进程 JSON 持久化适合高并发生产环境；
- 阻尼可以替代人工复核、评估集、回归测试或权限系统。

## 试点建议

1. 只在一个现场、一个域或一个规则族启用；
2. 先观察 `damping_decision`、补丁、冷却截止时间和人工接管次数；
3. 试点至少持续 2 至 3 周，并记录误判反弹、来回修复和人工介入；
4. 未取得可复现数据前，不把“启用阻尼”写成生产收益结论；
5. 试点无效时直接回滚对应补丁。

## 白皮书落点

- 白皮书第 7 章从四组件扩展为五组件，阻尼作为稳压器；
- 约束仍是“只调稳定性边界，不调业务对错”；
- 当前版本只能证明参考实现和测试行为，不能证明生产稳定性收益。
