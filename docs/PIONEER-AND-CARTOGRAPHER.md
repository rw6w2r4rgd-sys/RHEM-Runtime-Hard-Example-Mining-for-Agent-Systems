# 先驱与绘图师：关于“谁先谁后”的定位说明

**RHEM（Runtime Hard-Example Mining / 运行期难例挖掘）与难例发掘的关系**

---

## 一、走与指

难例发掘先走了这条路。它早已抬脚，在训练场里实践了“难样本值得挖”，路因此是真实的。但它走过之后，这条路没有被完整指出来：知道它存在的人，只有真正走到过它的人。

RHEM 做的是“指”：把这条路从“私人的足迹”变成“公共的地图”。

- 标出起点：它从难例发掘出发。
- 画全路线：回收 → 门控 → 并库 → 大模型数据前哨。
- 圈出禁区：护栏禁改域，写死不动。
- 昭告后人：命名、成文、发布、存证。

**走过的路会被草重新盖住；指出来的路，显了形、存了证、可传承，再见不散。**

## 二、两个角色，一张图

```text
难例发掘（先驱）：第一个探路，踩出第一步
                 价值 = 证明这条路通（存在）

RHEM（朝圣者绘图师）：真的走过，把经历画成图
                     价值 = 让所有人能走（可用）
```

- 先驱让“西域”不再是传说。
- 绘图师让“西域”对所有人不再神秘。

缺了先行者，没人敢说路通；缺了绘图师，通了也没人走得成。一文记“存在”之账，一文记“可用”之账。合起来，才是一条被后人真正踩出来的丝绸之路。

## 三、判据的转移

本方法的核心不在“谁先走”，而在判据的转移：

> 难例的定义，从“样本难不难”，改为“**会不会让系统绊倒**”。不看大小与新旧，凡致错皆管。

这一转移，使难例从“训练数据里的少数派”扩展为“运行期所有可能绊倒系统的错误”：识别、流程、规则、知识，全部纳入。

这也是 RHEM 比难例发掘更明确指路的地方。它不是画出一条更显眼的路，而是画出一条更长的路：从训练场一路标到运行期，并继续标到数据回流后的未来模型。

## 四、致后人

- 承难例发掘的先驱探路之劳。
- 立此图为续路、指路之用。
- 欢迎每一位沿图前行的人。

**概念被融合、被超越，是它最好的归宿。**
